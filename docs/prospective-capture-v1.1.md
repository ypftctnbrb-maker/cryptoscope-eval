## Snapshot and anchor

Freeze the source identity, venue and instrument, source/event time and collector observation time, fully closed candle interval and price inputs, feature coverage, pinned core file SHA/digest, decision time, scoring horizon and schema version. Store immutable canonical bytes keyed by their SHA-256 digest in an approved store. Store corrections under fresh digests and link the original. Preserve the receipt and input bytes before using the snapshot. Use UTC epoch milliseconds and decimal strings or fixed-scale integer prices under an explicitly versioned schema.

The bounded dry-run checks the timing and attribution envelope for one synthetic OKX spot market and five-minute candles. It accepts only the audited core source pin, fixed field shapes and market identifiers, and null CVD, OI and funding. It carries no price payload. The verifier hashes UTF-8 compact JSON with recursively sorted keys and safe integers. It verifies an Ed25519 signature over provider, digest and anchor time, using a key supplied by a trusted policy outside the snapshot. Anchor time must follow receipt of input and precede the decision. Verify independently that the operator is separate, the time semantics are trustworthy, the provider is free under the expected load, and its pinned public key and receipt format match policy. No production provider or key is configured. The ephemeral key proves local verification behavior only. Any unavailable, unverified, paid, forged or late receipt prevents acceptance.

Use the guard before submitting any candidate record. This draft exercises it before the code push through the offline fixture suite. It has no capture writer, hooks, scheduled jobs or automatic pushing. A production writer must invoke the guard at the write/push boundary with an approved immutable store and trusted policy. Bind the store, destination branch, session budget and explicit path allowlist at that boundary and refuse a push containing evaluation records or secrets until the controls are independently approved. The fixture schema rejects extra fields and prevents arbitrary strings in recognized fields. It is specific to evaluation records and is not a general Git secret scanner.

## Paired study preregistration proposal

Use the same frozen snapshot and fixed horizon for the zero-return baseline and each candidate. Observe the same venue, instrument, interval and native close for both. The first eligible closed bar opens strictly after the decision. Fix one five-minute horizon and absolute return error as the primary loss. Skip a pair if either arm or the matching outcome is missing. Report coverage and dropped pairs by venue and reason. Purge training outcomes crossing each cutoff, embargo by at least the largest overlapping input or outcome window and tune on training folds only.

For review, propose a minimum improvement of 1 bp absolute return error, two-sided alpha 0.05 and power 0.80 for one locked primary comparison. Define paired differences as baseline loss minus candidate loss. Keep synchronized observations across venues in each time block for shared shocks. Estimate long-run variance with HAC on time-indexed paired differences, with lag selection fixed from pilot autocorrelation and reported sensitivity. Validate with a moving-block bootstrap preserving the same time groups and missingness. An initial required count of time groups is ceil((1.96 + 0.84)² × long-run variance / (1 bp)²). Estimate duration from valid group arrivals and propagate uncertainty. Treat extra models and horizons as exploratory unless preregistered with multiplicity control. This dry-run produces neither variance nor a duration estimate.
